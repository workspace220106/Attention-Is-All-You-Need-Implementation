Positional Encoding Visualizer

Section 3.5 — Sinusoidal positional encodings let the model know token order without learned parameters.

Why positional encoding?

Unlike RNNs which process tokens sequentially, the Transformer processes all tokens in parallel. Without positional encoding, "The cat sat on the mat" and "mat the on sat cat The" would produce identical representations. The paper uses sinusoidal functions at different frequencies:

PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))

Each dimension uses a different frequency — from 2π (dimension 0) to 10000·2π (last dimension). This means the model can learn to attend to relative positions, because PE(pos+k) can be expressed as a linear function of PE(pos).

Position similarity matrix

Dot product between PE vectors. Nearby positions are more similar — the model can use this to learn relative distances.

Key insight from the paper: "We chose sinusoidal because it allows the model to extrapolate to sequence lengths longer than those encountered during training." The periodic structure means position 1000 uses the same wavelength patterns as position 10 — just at different phases.

From-scratch implementation

This is a real ML model running live. The network has an input layer (2 neurons for x,y coordinates), one or two hidden layers with configurable neuron count, and an output layer (1 neuron, sigmoid activation). Every weight is trained via gradient descent using the chain rule (backpropagation).

Forward:  z = W·x + b,  a = σ(z)        where σ(x) = 1/(1+e^(-x))
Backward: ∂L/∂W = ∂L/∂a · σ'(z) · x^T   (chain rule through each layer)
Update:   W ← W − lr · ∂L/∂W              (stochastic gradient descent)
